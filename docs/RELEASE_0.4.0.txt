V0.4.0 DERIVED RESEARCH EVIDENCE — RESEARCH RELEASE

Existing v0.3.0 application subset, validation records and scripts are preserved. The new studies are separate and must not be interpreted as using the earlier numerical configuration or contract coverage.

Included study directories:
1. revision_experiment_20261013: protocol, native fixtures, final case outcomes, baseline/oracle records, semantic control, performance raw samples and summaries, experiment implementation for inspection, and source identity hashes. There are 28 paired cases, ten accepted and eighteen seeded rejections per arm. The public verifier audits the saved outcomes and reconstructs metadata medians from 208 raw timings. A minimal numerical source_snapshot, with 60 unchanged modules and two disclosed initializer stubs, is included separately. The complete later application is omitted. The original run_experiment.py is archival inspection material because its full mechanical/ontology environment is omitted. reproduce_physics.py and run_performance.py are supported separate entry points.
2. maintenance_experiment_20261014: exact requests, solved 5/25 degree-C fixtures, evaluators, original and corrected checkpoints, original scores, post hoc results and change evidence. All original stages and the separate post hoc check can run from retained fixtures. The full later frozen_runtime is omitted.
3. semantic_integration_protocol_20261014: protocol, all synthetic provider snapshots, solved fixtures, evaluator, twelve checkpoint implementations and native exports, original acceptance records, metrics and independent review. All twelve original checkpoint acceptance arrays reproduce. Two RDF and two JSON implementations pass cumulative 40/48/56 checks. Only RDF1 changes its version guard (+3/-1 and +1/-1 lines); no query changes occur. Both representations contain equivalent shared semantics. No timing or human maintenance effect is measured here.

PUBLIC DERIVATION
The private source archives remain authoritative historical freezes. This reduced release is not byte-identical to those archives. PUBLIC_DERIVATION.json records original and public hashes for every selected study file. Machine-specific home, iCloud, workspace and temporary path prefixes are replaced with symbolic placeholders where present. Scores, physical values, source logic and case records are not intentionally changed. Original checkpoint hash manifests covering omitted work logs are omitted; public hashes apply to the reduced files. No logs, caches, credentials, environment files, complete application, screenshots or unpublished manuscript are included. Source manifests contain filenames and hashes only, not the omitted application itself.

REPRODUCTION
Install requirements_revision.txt under Python 3.12 and run scripts/verify_revision_evidence.py. No account or API key is needed. The command checks all included derived file hashes, reconstructs timing medians from original samples, audits recorded whole-process labels, reruns all provider-stage acceptance suites, and compares the adapter-pilot worker outputs to stored original scores. The post hoc RDF failure is expected at the original checkpoint and passes after the retained repair.

LIMITS
New acceptance uses stored outputs. Separate documented entry points support fresh 5/15/25-degree-C physical baseline execution and fresh metadata timing. They do not rerun all 28 paired integration cases or the full later mechanical/ontology runtime. Physical source hashes and the two packaging stubs are documented in PHYSICS_SOURCE_MANIFEST.json. The archived v0.3.0 scripts reproduce only the earlier version. Source-level integration code is supplied for inspection without implying that omitted later dependencies can be inferred from v0.3.0. Hash checks prove byte correspondence, not independent plant validation. Agent replicates are not human developers; synthetic providers are not independently sourced industrial organizations. General future capability classes were disclosed at baseline. Cumulative checks are not independent tasks.
