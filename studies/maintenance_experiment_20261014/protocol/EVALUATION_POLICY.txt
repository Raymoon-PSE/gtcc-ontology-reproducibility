Bounded agent maintenance pilot. Two sequential changes, one independently implemented RDF arm and one independently implemented JSON arm. Fresh implementer contexts receive identical requirements except assigned representation. Both start from identical frozen stores and canonical adapter. CHANGE_2 is released only after CHANGE_1 first-attempt acceptance results and checkpoint. Acceptance code is held out by instruction, not access-control. No claim of secure blinding or statistically independent developer samples.

Evaluator fixes the acceptance cases before inspecting candidate implementations. Requirement-based cases cover valid conversions, malformed native config, invalid payloads, input immutability, repeated configuration changes, all seven process boundary labels, three consumers, late failure, stale completion, history and copy isolation. Real whole-process numerical output is used as an additional fixture. This is real simulated boundary data, not plant measurements. Conversion examples have independent expected values; equality of arms alone is insufficient.

Each change gets an immutable first-attempt checkpoint, recorded acceptance results, and up to two repair rounds with only failing case IDs and observed errors supplied, not acceptance source. Retain all failures and repairs. Completion means all scoped acceptance checks pass or repair budget is exhausted, not proof of general correctness. Measure added/removed source lines and changed files from actual before/after checkpoints. Record self-reported debugging events separately from evaluator-observed failures. Do not infer human effort, actual time savings, independent incident rates or ontology superiority from one agent per representation or line count. Do not interpret seeded test counts as industrial frequency.

Report statistical limits prominently. This is a pilot of two successive adapter change requests, not independent professional developer trials, a model-integration productivity study, or a comprehensive full EKLM maintenance benchmark. Stop expanding tests after scoped correctness and regression gates pass. Preserve production EKLM and previous experiment. Deliver to a new separate folder inside EKLM_latest. No original manuscript changes or submission-readiness claim.
