Date: 2026-10-14

Finding
The recorded result is supported: all four independently implemented arms passed their original first-attempt suites at baseline, change 1 and change 2. The study establishes no RDF-specific integration or maintenance advantage in these scoped cases. It does not test shared semantic modeling against its absence: both representations contain the SAME engineering classes, explicit mappings, qualified identities, versions and validation semantics. Parity therefore does not show that a shared semantic model is useless. It shows that these capabilities were successfully realized in both RDF/RDFS and capable indexed JSON implementations.

Actual representation audit
RDF1 Model.one, Model.closure, Model.ancestry, Model.validate and Model.descriptor query its actual rdflib Graph. Local ancestry traverses RDFS.subClassOf; explicit mapsClass edges resolve canonical ancestry. Graph edges resolve boundary roles, fully qualified ports, versions, assigned equipment and field aliases/units. RDF2 import_graph builds the request graph; one/text, closure/classes, validate_metadata and read_endpoint use those facts for the same functions through canonicalClass and equipmentClass edges. Neither RDF arm substitutes a parallel JSON metadata registry. Their Python observation dictionaries associate incoming payloads with graph port nodes and are permissible transient numerical ingress indexes. Native Turtle artifacts serialize the graphs used by integration.
JSON1 and JSON2 use qualified tuple-keyed indexes and generic parent traversal with explicit canonical mapping joins. Both compute transitive closures from supplied relationships, validate metadata before observations, preserve namespace-qualified ports and perform per-request version/unit checks. JSON1 retains derived closures and asserted indexes. JSON2 retains derived closures and exports original metadata for primitive maps used during construction. This is a capable semantic-registry control, not deliberately weakened plain key lookup.
Both representations normalize both endpoints, compare their physical values and compositions, produce all seven canonical boundaries and implement the same three experimental query functions. No manual leaf-type lists, lexical class equivalence, expected physical-output tables, shared implementation validator/converter or evaluator-path dependency was found in the four adapters. Fixed boundary names and dimensional catalogs are explicit public API constants. RDF adapters import rdflib 7.6.0 plus standard libraries; JSON adapters use standard libraries. Import, validation, serialization helpers and query code are contained in the counted adapters.

Interpretation and confounds
RDF1 initially admitted only snapshot 1.0 and expanded its version whitelist at each release. JSON1 uses a general mapping/provider revision relation; RDF2 checks agreement without a release whitelist; JSON2 already admits the three publicly declared revisions at baseline. The tiny RDF1 source differences arise from version-policy architecture. They neither establish RDF overhead nor JSON superiority. RDF2's unchanged implementation directly demonstrates that the RDF1 edits were not required by RDF representation.
All baseline implementers received the general future capability classes, version scheme, dimensional rules and conflict semantics. Later exact provider snapshots were withheld, but architectural anticipation was allowed. Zero source edits across these announced changes should not be framed as adaptation to wholly unanticipated requirements. Both representations carry shared semantics by design; an ontology/shared-model-versus-no-shared-model causal comparison was not performed.
One fixture-author context created both synthetic providers independently of implementer contexts. A and B are not independent industrial organizations or separately maintained external systems. Four fresh implementer contexts provide two agent replicates per representation, not independent human developer samples or a population estimate. Exact model backend/sampling settings were unavailable and this is disclosed in RUN_LOG and arm logs; equal inherited configuration is the documented arrangement, not a verified exact backend/seed claim.
Seven solved GTCC boundaries and both endpoint exports, including cold-reheat and condensate returns, are included. Numerical fixtures reuse previously solved 5/25 degC outputs. This study does not rerun the solver, migrate the internal physical model, collect plant measurements, migrate existing diagnostic applications or measure prediction improvements. Three query functions are experimental consumers. No timing or human maintenance benefit follows from these results.

Decision
The host summary.json and RESULTS_README.txt accurately state the narrow outcome and preserve the shared-semantics control and version-policy confound. The fixed two changes are complete with all four replicates reported and no suppressed original failures. Retain the engineering-contract/representation-tradeoff framing. Do not claim RDF necessity, ontology superiority, reduced human effort or evidence that shared semantics have no value. Do not extend this study to search for a favorable representation outcome; journal fit and manuscript positioning should use the result actually obtained.
